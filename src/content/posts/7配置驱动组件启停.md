> 上一篇打通了端到端链路，但"启动哪些组件"仍硬编码在宿主里。这一天把它收进**一张登记表**：核心骨架固定启用，业务组件由自己配置段的 `enable` 决定去留。

---

## 一、这天做了什么

让同一个程序能"按需裁剪"：只想要用户服务、不想要其他功能时，**改一行配置**就行。

做法是把所有组件收进一张**登记表**，每项登记三件事：

```
名字        —— 启停、展示时用
工厂函数    —— 用它新建一个组件对象
是不是核心   —— 核心 / 业务
```

代码里就是 `component.go` 一行一个组件：

```go
// 源代码,位于 component.go（节选）
type component struct {
	name   string
	plugin GoTenon.PluginInfo
	cfg    any
	core   bool
}

var components = []component{
	{name: "mq",      plugin: mq.NewPlugin(),      core: true},
	{name: "flag",    plugin: flag.NewPlugin(),    cfg: os.Args[0:], core: true},
	{name: "config",  plugin: config.NewPlugin(),  core: true, cfg: config.Spec{...}},
	{name: "dialer",  plugin: dialer.NewPlugin(),  core: true},
	{name: "gateway", plugin: gateway.NewPlugin(), core: true},
	{name: "user",    plugin: user.NewPlugin()},   // core=false → 业务组件
}
```

- **核心组件**（mq / flag / config / dialer / gateway）：**固定启用**，配置里写了关也忽略；
- **业务组件**（user、视频、网盘……）：**看配置**决定开不开。

注册、启用、展示插件详情，全都读这一张表——统一管理就落在这里。

---

## 二、注册都做，启用才挑

有一个容易忽略的取舍：**停用的组件也要先注册**。

```go
// 源代码,位于 main.go（节选）
// 注册全部组件(停用的也注册:插件详情可见,且可随时由配置开启)
for _, c := range components {
	if _, err := m.Register(c.plugin, c.cfg); err != nil {
		panic(err)
	}
}
```

注册 = 入表，能被查询、能看描述、能随时启用；启用 = 真正走一遍装载、装配、上线。

两件事分开，才能做到"插件详情里看得见，但这一轮可以先不跑"。

---

## 三、核心固定、业务看配置

进入启动环节，先固定拉起核心骨架，再逐个检查业务组件启动状态：

```go
// 源代码,位于 main.go（节选）
// 启用核心骨架的其余部分(dialer / gateway):固定启用,配置不可关闭
for _, c := range components {
	if !c.core || utils.Contains(started, c.name) {
		continue
	}
	if err := m.Enable(c.name); err != nil { panic(err) }
	started = append(started, c.name)
}

// 启用业务组件:读各组件配置段的 enable 决定开关(目前为了方便开发设置为缺省启用)
for _, c := range components {
	if c.core { continue }
	if !utils.Bool(cfg.Section(c.name), "enable", true) {
		fmt.Printf("[宿主] 组件 %s 已按配置停用\n", c.name)
		continue
	}
	if err := m.Enable(c.name); err != nil { panic(err) }
	started = append(started, c.name)
}
```

```mermaid
flowchart TD
    R["遍历组件登记表"] --> Q{"core = true?"}
    Q -- "是" --> C1["固定启用"]
    Q -- "否" --> Q2{"配置段 enable?"}
    Q2 -- "缺省 / true" --> C2["启用"]
    Q2 -- "false" --> C3["跳过,打印'已按配置停用'"]
```

`started` 记下本轮真正启用的组件——停机时**逆序**卸载，依赖者先走。

---

## 四、开关写在组件自己的配置段里

配置文件的规矩是：**每一段就是那个组件的配置**。所以"要不要启用"也放在它自己的段里：

```yaml
user:
  enable: true
  dbWrite: ...
  redis: ...
```

值的优先级：**代码默认 < 配置文件 < 环境变量**。

## 五、跑出来什么

```
# 默认：用户组件是开着的
# 把配置里 user.enable 改成 false，重启：
[宿主] 组件 user 已按配置停用
# 再去访问 /api/user/... -> 404（路由根本没注册）
```

改一行配置，关掉一整块业务。
